# 法律智能助手（LegalAI）详细设计文档

> 技术栈：FastAPI + Vue 3 + PostgreSQL(pgvector) + DeepSeek API + RAG + Agent
> 版本：v0.1 设计稿（2026-10-24）

---

## 1. 系统概述

面向普通用户的法律 AI 助手，提供两大核心能力：

1. **法律问答**：基于法条知识库（RAG）的法律知识普及与咨询，回答附带法条引用。
2. **合同/协议分析**：用户上传 PDF/Word 文件，Agent 逐条审查，输出结构化风险报告。

所有 AI 输出均附带固定免责声明：
**"本内容仅作参考，不构成法律意见，不能代替执业律师的专业判断，请结合实际情况甄别。"**

### 1.1 合规与安全底线（必须在实现中落实）

- 密码 bcrypt 哈希存储，JWT 鉴权（access token 30min + refresh token 7d）。
- 文件按用户隔离存储（`uploads/{user_id}/{doc_id}/`），接口层强制校验归属。
- 每次回答末尾与页面固定位置展示免责声明。
- RAG 语料标注法条名称、文号、生效日期；检索不到依据时明确告知，禁止编造法条。
- 上传文件大小限制（≤20MB）、类型白名单（pdf/docx/doc/txt）。

## 3. 数据库设计（PostgreSQL + pgvector）

```sql
CREATE EXTENSION IF NOT EXISTS vector;

-- 用户表
CREATE TABLE users (
    id            BIGSERIAL PRIMARY KEY,
    username      VARCHAR(50)  UNIQUE NOT NULL,
    email         VARCHAR(120) UNIQUE NOT NULL,
    password_hash VARCHAR(128) NOT NULL,          -- bcrypt
    created_at    TIMESTAMPTZ DEFAULT now()
);

-- 会话表（一个会话包含多轮问答）
CREATE TABLE chats (
    id         BIGSERIAL PRIMARY KEY,
    user_id    BIGINT REFERENCES users(id),
    title      VARCHAR(200) DEFAULT '新对话',
    created_at TIMESTAMPTZ DEFAULT now()
);

-- 消息表
CREATE TABLE messages (
    id         BIGSERIAL PRIMARY KEY,
    chat_id    BIGINT REFERENCES chats(id),
    role       VARCHAR(20) NOT NULL,              -- user / assistant / system
    content    TEXT NOT NULL,
    citations  JSONB,                             -- 引用的法条 id 列表
    created_at TIMESTAMPTZ DEFAULT now()
);

-- 上传文档元数据
CREATE TABLE documents (
    id           BIGSERIAL PRIMARY KEY,
    user_id      BIGINT REFERENCES users(id),
    filename     VARCHAR(255) NOT NULL,
    file_type    VARCHAR(10)  NOT NULL,            -- pdf/docx/txt
    file_path    VARCHAR(500) NOT NULL,           -- uploads/{user_id}/{doc_id}/
    file_size    INTEGER NOT NULL,
    status       VARCHAR(20) DEFAULT 'pending',   -- pending/parsing/analyzed/failed
    created_at   TIMESTAMPTZ DEFAULT now()
);

-- 合同分析报告
CREATE TABLE analysis_reports (
    id           BIGSERIAL PRIMARY KEY,
    document_id  BIGINT UNIQUE REFERENCES documents(id),
    summary      TEXT,                            -- 总体评价
    risk_items   JSONB,                           -- [{clause, risk_level, problem, advice}]
    created_at   TIMESTAMPTZ DEFAULT now()
);

-- 法条知识库切片（RAG 核心）
CREATE TABLE law_chunks (
    id           BIGSERIAL PRIMARY KEY,
    law_name     VARCHAR(200) NOT NULL,           -- 如《中华人民共和国民法典》
    article_no   VARCHAR(50),                     -- 如 第二十六条
    chunk_text   TEXT NOT NULL,
    effective_at DATE,                             -- 生效日期，用于判断时效性
    embedding    vector(1024) NOT NULL            -- 与 embedding 模型维度一致
);
CREATE INDEX ON law_chunks USING hnsw (embedding vector_cosine_ops);
```

## 4. API 接口设计

统一前缀 `/api/v1`，除注册/登录外均需 `Authorization: Bearer <jwt>`。

### 4.1 认证模块 `/auth`

| 方法 | 路径 | 说明 | 请求体 |
|---|---|---|---|
| POST | /auth/register | 注册 | `{username, email, password}` |
| POST | /auth/login | 登录，返回 token | `{username, password}` |
| POST | /auth/refresh | 刷新 token | `{refresh_token}` |
| GET | /auth/me | 当前用户信息 | - |

### 4.2 会话与问答模块 `/chats`

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /chats | 会话列表 |
| POST | /chats | 新建会话 |
| GET | /chats/{chat_id}/messages | 历史消息（校验归属） |
| POST | /chats/{chat_id}/ask | 提问，**SSE 流式返回** |
| DELETE | /chats/{chat_id} | 删除会话 |

`POST /chats/{id}/ask` 请求：`{"question": "..."}`；SSE 事件流：
- `event: token` — 增量文本
- `event: citations` — `[{law_name, article_no, chunk_text}]`
- `event: done` — 结束（客户端随后渲染免责声明）

### 4.3 文档与分析模块 `/documents`

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /documents/upload | 上传合同（multipart），返回 doc_id，后台异步解析 |
| GET | /documents | 我的文档列表 |
| GET | /documents/{doc_id}/status | 解析/分析进度 |
| GET | /documents/{doc_id}/report | 获取结构化分析报告 |
| DELETE | /documents/{doc_id} | 删除文档（同时删文件与报告） |

分析报告结构（`risk_items` JSONB）：

```json
{
  "summary": "本合同整体…",
  "risk_items": [
    {
      "clause": "第八条 违约责任",
      "risk_level": "高 | 中 | 低",
      "problem": "违约金约定过高，可能超过法定上限…",
      "advice": "建议修改为不超过实际损失的 30%…",
      "legal_basis": "《民法典》第五百八十五条"
    }
  ]
}
```

## 5. Agent 与 RAG 设计

### 5.1 意图路由（Agent Router）

用户消息先经路由 Agent 判定意图，再分发：

| 意图 | 触发特征 | 处理流程 |
|---|---|---|
| 合同分析 | 消息携带 doc_id / 上传文件 | 合同分析 Agent |
| 法律咨询 | "劳动合同不签怎么办" 等 | 问答 Agent（RAG） |
| 闲聊/澄清 | 无法判定 | 追问澄清，不强行回答 |

### 5.2 问答 Agent（RAG 流程）

```
用户问题 → embedding → pgvector 相似检索 top-5 法条切片
        → 组装 prompt（问题 + 检索到的法条原文 + 规则）
        → DeepSeek 流式生成
        → 输出：回答 + 引用法条列表
```

**系统提示词核心规则（防幻觉）：**
1. 只依据提供的法条回答，不得编造条文编号或内容；
2. 回答中引用时标注 `《法律名》第X条`；
3. 若检索结果不足以回答，明确说明"现有知识库未找到相关依据，建议咨询执业律师"；
4. 不给出绝对结论，只分析可能性与一般规则；
5. 涉及刑事、紧急人身风险等情形，建议立即寻求当地法律援助或报警。

### 5.3 合同分析 Agent

```
上传文件 → parser 解析为纯文本（PyMuPDF/python-docx）
        → 按条款切分（正则识别 第X条 / 一、二、 编号）
        → 逐批送入 DeepSeek 审查（法条 RAG 辅助）
        → 汇总为结构化 JSON 报告（summary + risk_items）
        → 落库 analysis_reports，前端轮询后渲染
```

- 逐条审查而非一次性发送全文：避免长文截断，风险点覆盖更全。
- 每条风险必须给出 `legal_basis`，无依据的写"提示性风险"。

### 5.4 LLM 封装

- `services/llm.py` 封装 DeepSeek（OpenAI 兼容协议），统一超时、重试、限流。
- embedding 模型独立配置（如 BGE-m3 / text-embedding），维度与 `law_chunks.embedding` 一致。

## 6. 前端设计（Vue 3 + Pinia + Element Plus）

| 页面 | 内容 |
|---|---|
| Login / Register | 表单校验、token 存 localStorage、路由守卫 |
| Chat（主页面） | 左侧会话列表 + 右侧消息流；SSE 流式渲染 Markdown；消息下方展示"引用法条"折叠块与免责声明 |
| Documents | 上传（拖拽）、文档列表、状态徽标（解析中/已分析）、点击查看报告 |
| Report | 报告渲染：总体评价 + 风险条目表格（风险等级用红/黄/绿标签）+ 法条依据 + 页底免责声明 |

全局要素：所有 AI 输出组件统一挂免责声明组件 `<Disclaimer/>`；axios 拦截器统一处理 401 跳转登录。

### 7.1 风险与待办

- 法条语料来源需自行整理（公开法律法规文本），导入时逐条核对文号与生效日期。
- DeepSeek API Key、数据库密码等一律走 `.env`，不入库不入 git。
- 免责声明为固定文案，由后端在 `done` 事件与报告接口中统一附带，避免前端遗漏。
